# 口袋朗读员 — 离线中文 TTS 演示

把 AI Passport 变成随身朗读员。选择十二组中文示例之一，按确定听它读出来，
还可以比较六档语速。内容涵盖常用字、生活短句、数字、多音字、声调、标点和古诗。
语音由设备根据文本本地合成，不需要联网、账号或预录整句音频。

## 操作

- 上 / 下：切换上一句或下一句，同时停止当前朗读。
- 确定：开始或停止朗读。
- 长按确定：停止朗读，并循环切换 0（最慢）到 5（最快）六档语速。
- 开机持续按上键五秒：进入永久 Recovery 安装器。

屏幕显示文本、朗读状态、语速、启动时电量，以及实际输出音频时长与合成耗时。
合成耗时不包含阻塞的扬声器写入时间，不代表端到端延迟。
多音字、数字读法和语句节奏需要通过试听检查；本演示不保证覆盖某个完整常用字表。

## 构建与安装

使用 ESP-IDF **5.5.3**，ESP32-C3，**8 MB Flash**，无 PSRAM。

```bash
source /path/to/esp-idf-v5.5.3/export.sh
./tools/validate.sh
```

使用小程序安装经过校验的 `build/FoloToy-AI-Passport-full.bin`。
应用维持 3 MiB 以内，内嵌 929,972 字节的压缩语音库，不再需要独立语音分区。
校验流程核对内嵌资源和身份、Recovery 保护布局。USB 开发使用
`idf.py -p PORT flash`，分段写入引导程序、分区表和应用。
不要擦除设备或覆盖设备身份与永久 Recovery。

## 复用

`main/tts_runtime.h` 提供后台朗读任务。在 BSP 音频初始化后启动，再调用
`tts_runtime_say(text, speed)`，输入最长 240 字节的有效 UTF-8 文本。
新请求会替换旧朗读。API 由单个控制任务调用，后台任务独占 TTS 实例和音频写入。
详见[移植与验收说明](docs/development/engineering/chinese-tts.zh_CN.md)。

应用直接进入演示。显式退出函数会停用事件消费、等待后台任务退出，再删除屏幕。
若退出超时，会保留后台资源，不会强制删除阻塞在音频写入中的任务。

## 第三方分发

应用适配代码按本仓库许可证提供源码。ESP-TTS 引擎和语音模板采用上游
**预编译 RISC-V 库**，不等于完整可编辑的合成引擎源码。
`components/esp_tts/upstream.json` 记录确切上游版本与 SHA-256。

## 流式播放与空间预算

原编解码及变速路径在 C3 上合成 5.157 秒音频需要 6.625 秒，整句缓存是当时
避免断续的临时措施。压缩版改用 16 kHz 定点 Speex 解码器：正常语速按 20 毫秒
帧边解码边播放；其他语速只缓存一个音节，执行整数保持音高变速。
语音库先离线调整为原音节的 1.30 倍节奏，再压缩；六档相对制作后的声音为
0.80、0.90、1.00、1.10、1.20、1.30 倍，默认第 2 档不再实时变速。
没有整句缓存和 16 秒音频上限。文本请求仍限制为 240 字节 UTF-8；电子书调用方
应按句提交，并协调暂停、恢复和翻页。

保留原有发音词典及全部 1,749 条语音记录，语音库从 2,938,039 字节缩至
929,972 字节，减少约 68%。这是有损压缩，但保留 16 kHz 采样率；此前 8 kHz 版本被用户反馈声音闷，因此已替换。
1,749 条记录不等于 1,749 个汉字，覆盖范围仍由上游解析器决定。
原始大库只作为转换输入留在仓库，不烧入固件。

整个应用包含语音和界面约 1.68 MB。`0x360000`–`0x700000` 提供 3.625 MiB
连续空间，可由后续应用分区存书；当前 Demo 没有挂载电子书文件系统。
应用分区内部的剩余容量需另外计算。

USB 调试命令以换行结束：`TTS_DEMO_PLAY` 切换播放/停止，`TTS_DEMO_NEXT`
切换下一例，`TTS_DEMO_SPEED` 停止并切换语速，均走实体按键的控制路径。

解码器使用 BSD 许可的 Speex 1.2.1，分发时保留 `components/speex/COPYING`。
转换流程见移植说明。
