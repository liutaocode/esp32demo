# 深夜来电实现说明

应用采用确定性的分支叙事。`story.json` 是可编辑剧本；
`generate_night_call_story.py` 生成只读 C 数据表和 `voice_text.json`，后者是语音包实际朗读的字幕。
共 22 个节点、七个结局，每个节点两个选项。进入结局只结束当前通话。
隐藏终章要求结局位 2 和 4，即完成前两次真实救援；只读过线索还不够。

`night_call_state.c` 不依赖 SDK。24 字节版本化存档采用显式字节序、保留字节和 FNV 校验。
解码先验证章节与节点匹配、收集位范围，再替换当前状态。

按键回调只投递轻量事件，不等待。40 毫秒 LVGL 定时器处理事件并拥有界面对象。
使用单击而非按下事件，避免长按同时提交答案；长按上键重听、长按下键静音不会改变选择。
无需双击操作。删除画面前先移除页面与电量定时器，并清空待处理按键。

音频与存储工作任务随应用运行，不持有 LVGL 指针。音频每次解码 256 个采样，
从嵌入的 IMA ADPCM 包流式播放；代次编号用于取消旧语音，单槽队列保留最新请求。
播放、格式设置或任务创建失败时，完整字幕仍可使用。
NVS 用独立单槽队列写入 `nightcall` 命名空间，不会通过擦除存储来恢复错误。
不影响其他应用命名空间。保存提示消失前断电，可能丢失最近一次动作。

界面把共享像素边框调整为夜色配色。12、16、24 像素中文子集覆盖实际界面与剧本字符。
主机检查渲染真实 LVGL 对象树，检测占位字形、排除英文界面文字，
并测量全部节点和结局的文字边界、父容器裁切。
只读截图在持有 LVGL 锁期间，按全宽刷新条带传输交换字节前的像素；无需常驻帧缓存，
遇到异常条带顺序会拒绝截图。主机测试将完整 USB 数据与模拟屏幕接收的像素逐字节比较，
并测试短写入与故障恢复。本次准备未获取设备截图。

## 复现

```sh
python3 tools/generate_night_call_story.py
python3 tools/generate_night_call_audio.py --synthesize
python3 tools/generate_night_call_font.py
./tools/validate.sh
```

重新生成语音需 macOS Tingting、`say` 和 FFmpeg；已有 WAV 与打包文件可直接验证和构建，
无需重新合成。字体采用 LVGL 附带的思源黑体简体中文字体与 `lv_font_conv@1.5.3`。
`--check` 模式仅检查现有产物。完整校验需要固定版本的 LVGL 托管依赖及激活的 ESP-IDF 5.5.3。
实机验收和发布边界见审核包。
