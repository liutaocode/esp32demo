# 俄罗斯方块实现说明

[玩法与截图](../../../projects/clean-sweep/README.zh_CN.md)。

独立应用使用纯 C 状态机、真实 LVGL 页面、六事件静态按键队列和 12／16／24 像素专用中文字库，不初始化音频和网络。进入与退出需要持有 LVGL 锁；按键回调只投递按下和长按事件，LVGL 定时器负责推进状态和绘制。退出先关闭输入、删除定时器，再销毁页面。

十列二十行的井用一个 LVGL 对象加 `LV_EVENT_DRAW_MAIN` 直接画矩形，不给每个格子建对象：二百个格子若各建一个对象，仅样式和对象头就要吃掉几十 KB 内部 RAM，而本板没有 PSRAM。同一个回调负责网格、已落方块、落点虚影、当前方块和消除动画，因此闪烁、炸开、塌落都不需要额外对象。井只在棋盘状态变化时重画，消除动画期间按 40 毫秒一档重画，静止时不刷新。

确定键的三个动作分在按键组件的单击、双击和长按事件上。组件的状态机对同一次按下只会给出其中一个：长按之后不会再补发单击，双击也不会先发一次单击（`iot_button.c` 的 `PRESS_REPEAT_DOWN_CHECK` 只在 `repeat == 1` 时发单击）。因此旋转、落底和暂停天然互斥，不需要任何"先撤销刚才那次旋转"的补偿。方向键仍取按下瞬间，横向移动没有额外延迟；旋转要等短按窗口（180 毫秒）确认不是双击。

不要用 `iot_button_set_param()` 去缩短长按时间：注册回调时会把当时的长按时长存进 `event_args.long_press.press_time`，而 `PRESS_UP_CHECK` 要求它与当前的 `long_press_ticks` 相等才会回调，改了阈值就等于把长按回调静默关掉。本应用一度这样做过，主机测试发现不了，真机上表现为长按完全没反应。

## 构建和检查

在仓库根目录激活 ESP-IDF 5.5.3 后运行：

```bash
FAP_APP=clean_sweep ./tools/validate.sh
python3 tools/generate_clean_sweep_fonts.py
python3 tools/test_clean_sweep_ui.py
```

完整门禁包含纯状态测试：形状表、七连袋、重力、锁定宽限、消行动画三阶段、长按撤销、计分、连击、全清、冲刺收尾和结束判定。UI 程序使用已解析的 LVGL 依赖和共享主机桩，用启发式自动对局跑完整局，逐帧检查缺字、文字宽度、面板裁剪和越界，覆盖七种方块的全部朝向与列、四行齐消、全清、暂停、结果页、闲置暂停与调暗、按键降级，以及五十次退出重进，并输出 PPM 截图。

选择本应用不改变分区。主机渲染和固件编译不能代替实机测试。设备上应验证按下到移动的可见延迟、单击旋转与双击落底的手感、消除动画的流畅度和屏幕颜色、闲置调暗唤醒以及长时间运行。
